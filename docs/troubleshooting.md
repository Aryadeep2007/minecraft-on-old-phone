# Troubleshooting

Record observed errors and fixes here. When full verification is pending, the outcome column states that explicitly.

| Phase | Symptom | Cause | Verified workaround or outcome |
|---|---|---|---|
| Termux setup | A network-interface lookup reported a netlink socket permission error | Android restricted the interface query from Termux | Read the phone's local Wi-Fi address in Android Settings → Wi-Fi → connected network details |
| Termux setup | `ps -A -o PID,...` rejected the requested format | Android's bundled `ps` uses a different option set | `ps -A` worked to confirm whether the Java process was running |
| PaperMC | Paper logged JLine `libutil.so.1` and OSHI/JNA `libudev` native-library warnings | Optional native terminal and hardware probes could not load Linux libraries in the Termux environment | Paper reached `Done` and shut down cleanly; no workaround was needed for this startup |
| PaperMC | Netty could not find a hardware MAC address; Spark async-profiler could not load `libdl.so.2` | Android/Termux does not expose these Linux native libraries/interfaces in the expected form | Paper generated a random MAC fallback, reached `Done`, and shut down cleanly; Spark's optional async profiler remains unavailable |
| PaperMC | Paper printed command-line help and rejected an option on the first start-script launch | A Windows CRLF line ending added a carriage return to the final Java argument | Run `sed -i 's/\r$//' ~/minecraft-server/start.sh` on Termux; the LF-normalized script then reached `Done` and shut down cleanly |
| Bedrock connectivity | Floodgate warned that `en_` is not a supported language during startup | The phone's environment selected a locale identifier that Floodgate does not recognize | Floodgate still completed startup and Geyser started; player behavior has not been tested |
| Bedrock connectivity | NetherNet initialization failed with `Cannot identify the JVM's libc` after selecting `transport: both` | Geyser's current native library bundles glibc and musl builds, while Termux uses Android/Bionic | Restored `transport: raknet` and `webrtc-port: 0`; Geyser starts its UDP listener, but NetherNet remains unavailable in this Termux runtime |
| Bedrock connectivity | Debian `proot-distro` OpenJDK setup reported `proot warning: signal 11 received from process -1`; Geyser Standalone then failed with `InternalError: Error loading java.security file` | Debian's OpenJDK package remained unpacked, leaving security files as `.dpkg-new`; package configuration repeatedly terminated in PRoot | Debian did not work. Alpine 3.24.3 with musl and OpenJDK 21.0.12 successfully started Geyser Standalone 2.12.0-b1269 with NetherNet selected. Backend, Floodgate, client, and tunnel connections are still unverified |
| Java authentication | AuthMe's first Paper startup took about 5 minutes 45 seconds while downloading 15 declared libraries; startup log also warned that the optional GeoIP database could not be downloaded without MaxMind credentials | AuthMe initializes its libraries and SQLite database on first enable; GeoIP protection needs MaxMind credentials and is not required for basic password authentication | AuthMe 6.0.1 and PacketEvents 2.14.0 both enabled and Paper reached `Done`. GeoIP protection remains unavailable and has not been enabled or configured |
| 24/7 reliability | After a phone reboot, SSH returned before Paper was ready; startup logs included Spark's `libdl.so.2` native profiler warning and AuthMe's optional GeoIP database warning | Termux:Boot starts Paper automatically, but this phone takes several minutes to load Paper and plugins; Android/Termux lacks the native library Spark's optional async profiler expects, and GeoIP has no MaxMind database configured | Paper remained running, Geyser initialized, and Paper reached `Done (268.405s)! For help, type "help"` about 4 minutes 28 seconds after launch. The warnings did not prevent startup; wait several minutes before deciding startup failed |
| Bedrock connectivity | Geyser warned that NetherNet support is disabled and Bedrock players may not connect starting October 27, 2026 | The Paper Geyser plugin is still configured for RakNet in Termux; its attempted NetherNet transport cannot identify Android/Bionic, while the separate Alpine standalone test is not connected to Paper | Geyser's UDP 19132 listener starts, but future-version compatibility is not verified. Keep this limitation visible and do not claim all Bedrock versions can connect until the Paper backend's NetherNet path is working and tested |
| Java connectivity | The client reported `Connection refused` / `getsockopt` for the phone's Minecraft address | Paper had been launched in the foreground of an interactive SSH terminal; closing that terminal stopped the Java process, so nothing was listening on port 25565 | Start Paper detached with `cd ~/minecraft-server && mkdir -p logs && nohup ./start.sh >> logs/console.log 2>&1 < /dev/null &`. Verify the log contains `Done` and the port accepts a TCP connection. The setup computer reached port 25565 after this change; an actual Minecraft login is still unverified |
