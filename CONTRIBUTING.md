# Contributing

Thanks for helping improve this guide. Keep instructions beginner-friendly and reproducible.

## Before opening a pull request

- Describe the device, Android version, and relevant package/plugin versions.
- Verify commands on a device when practical; clearly label unverified suggestions.
- Update the phase guide and troubleshooting guide when a verified issue or fix changes.
- Use `.example` suffixes for sanitized configuration examples.
- Do not include credentials, IP addresses, SSH material, worlds, player data, server jars, or logs.
- Explain security implications for changes involving authentication, networking, dashboard access, or backups.

Use Conventional Commit messages when possible (for example, `docs: clarify Termux package setup`).
